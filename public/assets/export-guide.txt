================================================================================
MANIK.CC DESIGN SYSTEM — CSS EXPORT GUIDE
================================================================================

This guide documents the public CSS exported from manik.cc for reuse in other
projects. The export is intentionally CSS-only.

Source: https://manik.cc
Stylesheet: https://manik.cc/style/export.css
Repository: https://github.com/mnk400/mnk400.github.io


================================================================================
1. QUICK START
================================================================================

Minimal page:

    <!doctype html>
    <html lang="en" data-theme="linen">
    <head>
      <meta charset="utf-8">
      <meta name="viewport" content="width=device-width, initial-scale=1">
      <meta name="theme-color" content="#f2f0ef">

      <link rel="stylesheet" href="https://manik.cc/style/export.css">

      <!-- Optional, for closer font parity outside manik.cc. -->
      <link rel="stylesheet" href="https://rsms.me/inter/inter.css">

      <!-- Optional, if your markup uses Phosphor icon classes. -->
      <link rel="stylesheet" href="https://unpkg.com/@phosphor-icons/web@2/src/regular/style.css">
      <link rel="stylesheet" href="https://unpkg.com/@phosphor-icons/web@2/src/bold/style.css">
    </head>
    <body>
      <div class="wrapper stack">
        <h1>Hello</h1>
        <p>Shared styling, local behavior.</p>
        <a class="btn" href="/">Button link</a>
      </div>
    </body>
    </html>

No JavaScript files are exported. Components that need behavior should be wired
by the consuming project.

2. WHAT THE STYLESHEET INCLUDES
================================================================================

/style/export.css is generated from src/styles/export.scss and includes:

    partials/base/variables        Theme tokens, spacing, radius, shadows, z-index
    partials/base/mixins           Compile-time helpers used by component styles
    partials/base/reset            Browser reset and basic element normalization
    partials/base/typography       Typography, links, headings, code
    partials/layout/wrapper        .wrapper layout container
    partials/components/buttons    .btn, .normal-btn and button variants
    partials/components/copy-button  .copy-button feedback state
    partials/components/expandable-section  .expandable-section, -toggle, -content
    partials/components/selection-switch    .selection-switch and .switch-option
    partials/components/search-pill .search-pill, trigger, field, clear
    partials/components/cards      .card, reveal card surfaces, .album-item
    partials/components/grids      grid helpers and page-agnostic grid primitives
    partials/components/image-gallery  gallery shell, masonry grid, image cards
    partials/components/info-grid  .info-grid and .info-card
    partials/components/forms      bare inputs, select, colour input
    partials/components/control-group  .control-group and its parts
    partials/components/selection-dropdown  .selection-dropdown and its parts
    partials/components/image-upload        .image-upload and its parts
    partials/components/range-slider  .range-slider and .range-slider__value
    partials/components/image-zoom Image zoom overlay classes
    partials/components/icon       .icon sizing and alignment

One component owns one partial: the .astro file, its root block class, and its
SCSS partial share a name. Deleting a component deletes all of its CSS.
partials/components/forms holds only bare elements no component owns.
    partials/utilities/helpers     .stack, .cluster, .toolbar and utilities
    partials/utilities/reveal      reveal animation helper classes

It does not include page-specific styles, site header/footer styles, view
transition rules, or JavaScript.


================================================================================
3. THEMES
================================================================================

Set a theme with data-theme on the html element:

    <html data-theme="charcoal">

Available themes:

    linen, charcoal, denim, plum, moss, butter, espresso, blush, sky

The default visual baseline is linen.

Theme tokens:

    --background-main
    --background-darker
    --text-color
    --sec-text-color
    --contrast-overlay
    --contrast-overlay-hover
    --translucent-low
    --translucent-medium
    --translucent-high
    --code-bg

If your project wants persistent theme selection, own it locally:

    <script>
      (function () {
        var themes = ['linen', 'charcoal', 'denim', 'plum', 'moss', 'butter', 'espresso', 'blush', 'sky'];
        var stored = localStorage.getItem('theme');
        var theme = themes.indexOf(stored) === -1 ? 'linen' : stored;
        document.documentElement.setAttribute('data-theme', theme);
      })();
    </script>

6. BUTTONS
================================================================================

Basic buttons:

    <button class="btn" type="button">Save</button>
    <a class="btn" href="/download">Download</a>
    <button class="normal-btn" type="button">Convert</button>

Variants:

    .btn--small
    .btn--outline
    .btn--text
    .btn--copy
    .btn--dark-forced
    .btn--link-variant

Copy button visual contract:

    <button class="normal-btn copy-button" type="button"
            data-copy-button data-copy-value="Text to copy" aria-live="polite">
      Copy
    </button>

Add .is-copy-feedback while replacing the label with confirmation or error
text. The Astro component and clipboard runtime are site-side and are not
included in the CSS-only export.


================================================================================
7. FORM CONTROLS
================================================================================

Inputs:

    <input type="text" placeholder="Name">
    <input type="email" placeholder="Email">
    <input type="url" placeholder="URL">
    <select>...</select>

Control group visual contract:

    <div class="control-group">
      <label class="control-group__label" for="size">Size</label>
      <input id="size" type="text">
    </div>

Use .control-group__control around controls that should share one inline row.
Use a span instead of a label for composite controls without a native input.

Range slider visual contract:

    <div class="range-slider" style="--value-percent: 50%">
      <input type="range" min="0" max="100" value="50">
      <output class="range-slider__value">50</output>
    </div>

The output overlays the track, right-aligned with the standard large inset. Its
foreground splits at --value-percent so it stays legible across both the filled
and unfilled portions.

Selection switch visual contract:

    <div class="selection-switch" aria-label="View">
      <button class="switch-option active" type="button">Grid</button>
      <button class="switch-option" type="button">List</button>
    </div>

Search pill visual contract (was .site-search before the 2026-08 rename, see
section 12):

    <div class="search-pill">
      <button class="search-pill__trigger" type="button" aria-expanded="false">
        Search
      </button>
      <label class="search-pill__field">
        <input type="search" placeholder="search">
        <button class="search-pill__clear" type="button" hidden>x</button>
      </label>
    </div>

Add .is-open or .has-query to .search-pill to swap the trigger for the field.
.search-pill--small is the compact resting size.

Selection dropdown visual contract:

    <div class="selection-dropdown">
      <button class="selection-dropdown__trigger" type="button" aria-expanded="false">
        <span class="selection-dropdown__trigger-text">Latest first</span>
      </button>
      <div class="selection-dropdown__menu collapsed" role="listbox">
        <button class="selection-dropdown__option active" type="button" role="option">Latest first</button>
      </div>
    </div>

These are styles only. Open/close, active state, keyboard handling, and slider
fill updates belong to the consuming project.

8. CARDS AND GRIDS
================================================================================

Basic card:

    <article class="card">
      <h2>Title</h2>
      <p>Description</p>
    </article>

Info grid:

    <div class="info-grid info-grid--cards">
      <article class="info-card">
        <span class="info-card__icon" aria-hidden="true">...</span>
        <h3 class="info-card__title">Fast</h3>
        <p class="info-card__body">Short explanation.</p>
      </article>
    </div>

Image grid classes are included for projects that share album/gallery layouts:

    .image-gallery__grid
    .masonry-column
    .image-card
    .image-ratio-box

Async galleries can add .is-deep-link-pending to .image-gallery while resolving
a selected item. Direct .reveal__stage children remain concealed until the
lightbox is ready, preventing staged grid/control content from flashing first.
The pending rule also settles opacity and transform; once .is-ready is present,
removing it reveals the same final state without replaying entrance transitions.

The manik.cc gallery runtime lives in `src/lib/image-gallery/`, split by
responsibility: `data.ts` normalizes and queries manifests, `view.ts` owns
cards, controls, masonry pagination, and rendered-image lookup, and `route.ts`
owns the `?image=` URL and Back/Forward synchronization. `index.ts` is the
public lifecycle coordinator between those modules and the zoom viewer. The
route installs one capture-phase owner because a page has only one `image`
query value; no layout script or global handler registry is needed.

Use an `aspect-ratio` on `.image-ratio-box` to reserve gallery item height. The
image fills that ratio box with `object-fit: contain`, so thumbnails are not
cropped when the source image ratio differs from the reserved ratio.


================================================================================
9. IMAGE ZOOM STYLES
================================================================================

The CSS includes the overlay classes used by manik.cc's image zoom runtime:

    .image-zoom-overlay
    .image-zoom-overlay--closing-direct
    .image-zoom-backdrop
    .image-zoom-viewport
    .image-zoom-slide
    .image-zoom-image
    .image-zoom-clone
    .image-zoom-clone--direct
    .image-zoom-controls
    .image-zoom-palette
    .image-zoom-palette__dot
    .image-zoom-palette__swatch
    .image-zoom-meta
    .image-zoom-caption
    .image-zoom-detail
    .image-zoom-control-button
    .image-zoom-share

For a directly opened image, `.image-zoom-overlay--closing-direct` is the sole
visual closing state. Its descendant rules fade/scale the clone, fade controls,
and delay the backdrop fade; JavaScript only adds the class and schedules final
teardown.

`.image-zoom-overlay` is a native modal `<dialog>`, so the browser owns focus
containment and document inertness. `.image-zoom-viewport` is the persistent
horizontal scroll container; it lays out one `.image-zoom-slide` per item with
mandatory center snapping. Touch, trackpad, keyboard, and edge-button input all
move this same native scrolling surface. If any gallery item has metadata, keep
`.image-zoom-overlay--has-meta` set for the full dialog session so the caption
rail never changes the image viewport's geometry during navigation. The image
stage uses equal top and bottom insets, keeping every image vertically centered
while the caption occupies the lower safe area.

While the dialog is open, the component CSS fixes the body at custom-property
offsets supplied by the runtime. Preserve the window offset before
`showModal()`, then remove those offsets and restore the window position when
the dialog closes. This prevents background scrolling without Chrome resetting
the page to the top.

The `.image-zoom-clone` is temporary. It morphs between a gallery thumbnail and
the current `.image-zoom-image` only while the dialog opens or closes, then is
removed. Gallery navigation never creates overlapping clones.

Populate `.image-zoom-palette` before activating `.image-zoom-controls`, so its
initial appearance shares the controls' opacity transition instead of arriving
later. Keep the dot elements mounted during gallery navigation and update their
swatch background colors in place; the CSS color transition avoids exposing the
page background or requiring temporary overlapping palette layers.

The JavaScript runtime is not exported. Astro projects can copy
`src/lib/image-zoom/` plus `ImageZoomTemplate.astro` if they want the same
behavior, but should import only `image-zoom/index.ts`. Non-Astro projects should
either supply equivalent template markup, implement their own runtime against
these classes, or use a dedicated lightbox library.
`image-zoom/index.ts` is the public controller; `view.ts` and `motion.ts` are
private implementation modules. The runtime
exports openZoom(img), closeZoom(),
and openZoomGallery(items, initialIndex, options). Data-backed gallery items use
stable IDs plus thumb/full sources and optional title, metadata, dimensions, and
origin elements. This allows navigation across items that are not mounted in
the DOM. Direct sessions cross-fade without inventing a thumbnail origin;
pointer-opened sessions return to their source. The runtime also provides dialog
semantics, focus containment/restoration, keyboard activation,
reduced-motion transitions, and an optional copy-link control for data-backed
sessions. Keep mutable viewer state in one session object, invalidate it on
teardown, and verify session identity after asynchronous image decoding or frame
yields. Model lifecycle as `opening`, `open`, or `closing`; horizontal scrolling
owns navigation and updates the current item as slides cross the viewport center.
Session-owned AbortSignals remove interaction listeners together.


================================================================================
10. REVEAL HELPERS
================================================================================

Reveal classes are CSS-only animation helpers:

    <div class="reveal">
      <div class="reveal__stage reveal__stage--1">First</div>
      <div class="reveal__stage reveal__stage--2">Second</div>
    </div>

Use .is-ready on the root when your project is ready to reveal async content:

    document.querySelector('.reveal').classList.add('is-ready');


================================================================================
11. ICONS
================================================================================

The export styles a generic .icon class, but it does not ship icon assets.
Use your own inline SVGs or load Phosphor/Iconify/etc. in the consuming project.

Example with Phosphor web classes:

    <i class="ph-bold ph-arrow-up-right icon" aria-hidden="true"></i>

12. VERSIONING NOTES
================================================================================

Breaking changes:

    2026-08  .site-search* renamed to .search-pill* so the class matches its
             component (SearchPill.astro) and partial (_search-pill.scss).
             Affects .site-search, __trigger, __field, __clear, --small and the
             --site-search-* custom properties. No declarations changed; if you
             consume export.css, rename the classes in your markup.

This export is a visual CSS contract, not a full component runtime. The stable
public URL is:

    https://manik.cc/style/export.css

The guide is available at:

    https://manik.cc/assets/export-guide.txt

If a future project needs portable behavior, prefer a narrow ESM module for that
single behavior instead of reviving broad global scripts.
